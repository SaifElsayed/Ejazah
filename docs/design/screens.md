# Screen inventory

Every board of the design (`frames/`, 183 boards) mapped to its implementation: the route, its kind, the
feature folder that owns it, the requirement ids it realises, the data it shows, every action and its
destination, and what the implementer must know (ADR 0020 D5). The boards are the visual source; the
rows below are the map. Sample values on the boards (people, dates, amounts) are `source/FACTS.md`'s
data, never copy; the copy is the i18n catalogue (`apps/mobile/src/i18n/`, `apps/admin/src/i18n/`).
What the inventory found undrawn or undecided is `open-items.md`.

## Conventions

- **Routes.** Expo Router under `apps/mobile/src/app/`: `(auth)/…`, `(student)/(tabs)/…` and
  `(student)/…`, `(teacher)/(tabs)/…` and `(teacher)/…`; shared routes outside the role groups
  (`session/[id]`, `chat/[enrollmentId]`, `notifications`, `time-zone`, `terms`, `restricted`);
  public web pages as `web /…` (where they are served is an open decision); admin pages as the Vite
  SPA's paths (`apps/admin/src/pages/<name>/`).
- **Kind.** `tab root` · `screen` · `sheet on <route>` · `dialog on <route>` · `state of <route>: <which>`
  (a drawn state of the same screen: empty, error, offline, English, dark, an alternative record) ·
  `reference` (a documentation board) · `proposal (undecided)` (an alternative awaiting the owner).
- **Feature.** `student/<feature>`, `teacher/<feature>`, `shared/<feature>` under
  `apps/mobile/src/features/`; a sheet belongs to the feature of the screen it opens on.
- **SRS.** Requirement ids from `docs/SRS.md` and the decisions of ADR 0012–0019 that amend it.
- **Actions.** `label → Board` for navigation, `(closes)`, `(in place)` and `(system)` for the rest.

disabled until the mandatory field is written, the audit footer. Whether approvals should carry an
optional note instead of a mandatory one is in `decisions-2026-10.md` (item 28).

# States to implement that are not drawn

For each list or network-backed screen: which of loading, empty, error and offline the design draws
(the board), and which it leaves to the generic patterns (`Skeleton`, `EmptyState`, a danger
`Banner` with retry, the `MainOffline` pattern).

A cell that names a board is drawn (the 2026-10-17 pass added the empty states that needed their
own copy); a cell that names keys uses the generic component with that copy; "generic" means the
component with its default copy (`common.state.loadError`, `common.state.offline`, `common.action.retry`).
