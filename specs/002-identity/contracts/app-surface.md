# Contract: The user surface

Every procedure below is mounted on `appRouter`. Kind, input, output, rate
limit and the requirement it serves. A public procedure declares its rate
limit; the user kinds declare their standing (`admits`) and whether a
restricted account may call them. "user" is the new `userProcedure` kind:
any authenticated person of either role, for what both roles share
(contracts/kernel.md).

## `auth` — sign-in (FR-120 to FR-123, FR-129, FR-135)

| Procedure                         | Kind                                | Input                                                                         | Output                                                                                                                                                         | Notes                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth.signInWithProvider`         | public, `rate_limit_authentication` | `{ provider: 'google' \| 'apple', identityToken, nonce, authorizationCode? }` | `{ outcome: 'session', accessToken, refreshToken, landing }` or `{ outcome: 'onboarding', onboardingToken, prefill: { displayName?, email?, emailVerified } }` | Verifies through the sign-in port (R-103). An existing identity yields a session and `landing` (`student_home`, `teacher_application`, `teacher_home`, `restricted`); a new one yields the onboarding token. `EMAIL_IN_USE_BY_OTHER_METHOD` when the verified email belongs to another account (FR-123). Apple's `authorizationCode` is exchanged for the refresh token kept for revocation |
| `auth.email.requestSignUpCode`    | public, `rate_limit_one_time_code`  | `{ email }`                                                                   | `void`                                                                                                                                                         | Always the same answer, and a code is sent for every well-formed address, so nothing is enumerated; a conflict is told only after the code verifies                                                                                                                                                                                                                                         |
| `auth.email.verifySignUpCode`     | public, `rate_limit_one_time_code`  | `{ email, code }`                                                             | `{ onboardingToken }`                                                                                                                                          | `CODE_INVALID` for wrong, expired or spent; once the code verifies, `EMAIL_IN_USE_BY_OTHER_METHOD` with the method when the address already belongs to an account, so the conflict reaches only someone who controls the mailbox                                                                                                                                                            |
| `auth.email.signIn`               | public, `rate_limit_authentication` | `{ email, password }`                                                         | `{ accessToken, refreshToken, landing }`                                                                                                                       | `SIGN_IN_FAILED`, one message. The password is verified only after the throttle (FR-135; the PR #46 decision in PLAN.md); an unknown email verifies against a decoy hash (R-107's timing rule)                                                                                                                                                                                              |
| `auth.email.requestPasswordReset` | public, `rate_limit_one_time_code`  | `{ email }`                                                                   | `void`                                                                                                                                                         | Same sentence for every address (decision 4). A provider address gets no code                                                                                                                                                                                                                                                                                                               |
| `auth.email.resetPassword`        | public, `rate_limit_authentication` | `{ email, code, newPassword }`                                                | `{ accessToken, refreshToken, landing }`                                                                                                                       | `PASSWORD_WEAK` by R-105; signs in and revokes every other session (`password_reset`)                                                                                                                                                                                                                                                                                                       |
| `auth.refresh`                    | public, `rate_limit_authentication` | `{ refreshToken }`                                                            | `{ accessToken, refreshToken }`                                                                                                                                | Rotation with reuse detection (R-101); a reused token revokes the session and answers `UNAUTHENTICATED`                                                                                                                                                                                                                                                                                     |
| `auth.signOut`                    | user, `admitsRestricted`            | `void`                                                                        | `void`                                                                                                                                                         | Revokes the device's session (`sign_out`)                                                                                                                                                                                                                                                                                                                                                   |

Password schema (in `packages/contracts`): `z.string().min(8).max(128)`;
the breached check is the service's. Email schema: `z.email()` lower-cased by
the service for comparison (the column is `citext`).

## `onboarding` — the first sign-in (FR-124 to FR-127)

| Procedure                     | Kind                                | Input                                                                                                                                                            | Output                                   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `onboarding.requestEmailCode` | public, `rate_limit_one_time_code`  | `{ onboardingToken, email }`                                                                                                                                     | `void`                                   | Only for a token whose identity has no verified email (FR-122); writes a `signup` code for the address                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `onboarding.complete`         | public, `rate_limit_authentication` | `{ onboardingToken, role: 'student' \| 'teacher', displayName, gender: 'male' \| 'female', dateOfBirth, timezone, termsVersion, password?, email?, emailCode? }` | `{ accessToken, refreshToken, landing }` | One transaction: `users`, `auth_identities` or `password_hash` (from `password`, required exactly when the token's identity is an email and refused otherwise), `user_roles`, `terms_acceptances`; a session only then (FR-125). `termsVersion` must equal the `terms_version` setting. `timezone` must be an IANA zone the time package knows. `email` and `emailCode` are required exactly when the token's identity has no verified email. The token's `jti` is claimed once (R-102). `landing` is `student_home` or `teacher_application` |

The email sign-up path: `verifySignUpCode` returns a token whose identity is
the verified email; the password chosen on `EmailSignUp` is held on the device and sent with
`complete` as `password`, the optional input above, required exactly
when the identity is an email. Nothing of the person is stored before
`complete` commits.

## What every procedure of this surface guarantees

- Its output schema names every field a client may see; the leak test asserts
  that none names `dateOfBirth` of another person, a storage key, a hash, a
  provider subject or a recipient reference (FR-138).
- No input names `gender`, `role`, `userId` (T159) and none names a timestamp
  (R-TIME-6); `onboarding.complete`'s `gender` is the one exception the rule
  admits by design — it is the declaration itself, made once by the person
  before any account exists, and the lint rule's allow-list names that single
  procedure and no other (R-GENDER-6's test asserts the allow-list has exactly
  one entry).
- Every mutation a client may retry (`onboarding.complete`,
  `teacher.application.submit`, `account.delete`, `teacher.payout.register`)
  takes the kernel's idempotency key, now per actor (FR-106); `complete` is
  keyed by the onboarding token's `jti`.
