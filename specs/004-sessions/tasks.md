# Tasks: Phase 3 — Live sessions

**Input**: Design documents from `/specs/004-sessions/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: Included, and not optional, as in Phases 1 and 2: tests before implementation, each observed red for the right reason; every job with its double-run spec (R-API-14), the four new ones included; every procedure under the coverage floor, `modules/chat` joining it (T054); every procedure that issues a token or reads a session, its chat or its counterparty in the adversarial suite, both directions (FR-496); every video event in a spec produced by the stand-in harness over HTTP (T010, contracts/video.md), as the gateway's harness is for payments (`003:T013`); every lock and FK-insert path checked against `003:T005`'s two rules, with a probe in `tests/db-integrity/` where the database cannot hold the rule (data-model.md §5). Every run is on `ijazah_integrity` only (both URLs checked, `IJAZAH_DB_SPECS=1`), never on `ijazah`.

**Organization**: The carried tasks first (they keep their lines, notes and `[x]` marks in their own files; this file places them, and writes three of them as its own tasks, as `003:T010` wrote `002:T143`), then the foundations, the seven stories of spec.md in priority order, the proofs and the close, and Phase 4's Spec Kit cycle. Task ids follow the order of the batches, B33 to B43, so a story's tasks are not contiguous. The batches at the end are the unit of delivery: one branch, one pull request, one review by Saif's review session, which checks every lock and FK-insert path against `003:T005`'s rules, at most six tasks (PLAN.md; plan.md, "Batch plan").

**The owner's window rule of 2026-11-05** (plan.md, "Decisions recorded", decision 9's H1 to H5 and decision 14; research R-320): no time is shown or offered that starts before the window it waits on can end. The tasks that apply it each name the window and what is hidden, with a spec for each bound: T021 (a cancellation request), T027 (reservations, H3), T028 (the system's proposal, H1), T029 (a make-up's booking reads the reservations again), T031 (the counter-proposal's options, H2 and H4), T032 (the release of a reserved time, H3, and the choice window's end, H5).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel — different files, no dependency on incomplete work

- A task of `specs/003-booking/tasks.md` is written `003:T059`, one of `specs/002-identity/tasks.md` `002:T144`; a bare id is this file's. Every task names its file paths.
